# Подготовка экрана снаряжения

31 октября 2026. Целевой сценарий: пользователь открывает снаряжение через1–2 секунды после экрана персонажей. Переход не блокируется загрузкой ресурсов.

## Изменения

- Вместо 19 крупных оружейных WebP (3203002 байта) и 14PNG бонусов (1505980 байт) экран использует 2 подготовленных атласа: оружие239872 байта, бонусы229974 байта. Всего469846 байт вместо4708982 байт (−90,0%). Крупные оригиналы и боевые спрайты сохранены.
- Карточки оружия240×380 заранее повёрнуты и вписаны в прежнюю область208×340. Бонусы192×192. Кодирование прямо из оригиналов, WebP quality 90 / alpha 100. Все 19 пар оружия и 14 пар бонусов осмотрены рядом с прежней графикой: угол, ориентация и кадрирование сохранены; значимого ухудшения в карточках не обнаружено. Пиксельная идентичность не заявляется.
- Резервные картинки — встроенные WebP-превью, а не отличающиеся по виду векторные рисунки. Их 79976 байт; генератор контролирует бюджет 80 КБ. Дополнительная цена начального JS — около80 КБgzip. Итоговый JS примерно255 КБgzip, обычное предупреждение Vite о чанке более500 КБ доgzip сохраняется.
- Скрытый экран и изображения начинают готовиться уже в главном меню. Музыка меню и необязательная фоновая подготовка боя ждут подготовки снаряжения; явное «Играть» остаётся независимым. Фоновая очередь прочих крупных портретов ограничена одним запросом, выбранный портрет имеет высокий приоритет.
- Декодирование двух атласов и подготовка карточек идут независимо: ошибка оружия не блокирует бонусы. Неудачный запрос можно повторить без загрузки успешного. PNG для img и анимации перелёта создаются один раз с уступкой основному потоку между карточками.
- Повторное открытие не пересоздаёт DOM, если герой тот же. Асинхронная готовность меняет только src действующих img, сохраняя выбор, фокус, прокрутку и совместимость с EquipmentFlight. Для другого героя карточки перерисовываются с его комплектом.

## Проверка

345 тестов, TypeScript, production build и `npm run assets:equipment:check` проходят. Новая регрессия проверяет встроенные превью без запросов, два общих атласа, независимую готовность, повтор только неудачного запроса и отсутствие обновления удалённого экрана.

Edge headless,1440×900, холодные контексты; сеть CDP80 мс/600 КиБ/с. По одному прогону каждого сценария; это не точная копия пресета DevTools и не статистическая оценка.

| Сценарий | Открытие вкладки | Дополнительное ожидание всех полных карточек |
| --- | ---: | ---: |
| После изменения, через1 секунду |45 мс|1354 мс|
| После изменения, через2 секунды |39 мс|409 мс|

Во всех случаях превью изображений уже видимы при открытии, переход не ожидает полного качества. Устранение ожидания полного разрешения на произвольной медленной сети не обещается. Прежний сценарий с переходом через1 секунду открывал вкладку за346 мс и продолжал ждать крупные ресурсы; исследовательский замер24623 мс включал также завершение фоновых портретов и не является чистым временем загрузки оружейных карточек, поэтому прямой множитель ускорения по нему не приводится.

В браузере проверены выбор дробовика и серебряной аптечки, сохранение фокуса/набора, анимация переноса, переход назад и повторное открытие. Ошибок JS нет. Артефакты: `output/equipment-qa/`, сравнительные листы `output/equipment-art-check/`.

Генерация: `npm run assets:equipment`; проверка: `npm run assets:equipment:check`. Манифест содержит SHA256  исходников, экспортов и исходной разметки оружия. Исходники не изменены.
