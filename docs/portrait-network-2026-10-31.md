# Портреты, аватары и активки на ограниченной сети

Повторная доработка 31 октября после проверки пользователем через Network → Fast 4G.

## Причины и изменения

- Скрытая вкладка улучшений создавала 10 запросов изображений общим размером 960 713 байт при открытии персонажей. Теперь `prepareArtwork()` назначает `src` только при открытии вкладки.
- Первый клик меню вызывал `CombatAudio.unlock()` и загрузку 21 WAV одновременно с портретами. Теперь unlock только создаёт/возобновляет AudioContext. Отдельный общий `preload()` загружает звуки с низким приоритетом после готовности выбранного портрета, аватаров и иконки способности. Запуск боя и явный предпросмотр сохраняют резервный вызов preload.
- 13 иконок активок: PNG 256×256 заменены игровыми WebP 192×192, 2 066 562 → 173 178 байт (−91,6%). Исходники сохранены. Генератор: `node scripts/optimize-abilities.mjs`, проверка: тот же вызов с `--check`.
- 15 нижних аватаров объединены в один WebP-атлас 960×864: 225 200 байт, один запрос вместо 15. Генерация непосредственно из уменьшенных оригиналов, без повторного сжатия существующего WebP. Настройки и карта ячеек сохранены рядом с атласом; `node scripts/optimize-roster.mjs --check` проверяет воспроизводимость. При ошибке атласа интерфейс пробует отдельные миниатюры.
- В большом портрете сначала отображается лёгкая миниатюра, затем декодированная полная версия. Проверка ревизии не позволяет поздней загрузке подменить нового выбранного героя. Боевые Canvas-изображения запрашиваются с низким приоритетом; фоновые загрузки ждут видимых элементов выбора.

Крупные портреты не пересжаты. Атлас и активки используют сжатие с потерями. Сравнения всех изображений осмотрены; заметного ухудшения в игровом размере не обнаружено. Для атласа разница с прежними миниатюрами измерена как RMSE 2,97/255 по RGBA — это не побитовое совпадение.

## Локальный замер

Production до/после, Edge headless, 1440×900. CDP: задержка 150 мс, скорость загрузки 200 КиБ/с. Это явно заданный ограниченный профиль, а не утверждение о точном соответствии пресету Fast 4G конкретной версии DevTools. Новый context для холодного кеша, повторная навигация в том же context для тёплого. Замер от клика «Выживание» до готовности изображения (`decode`), для аватаров — всего ряда. До изменений использована копия предыдущей production-сборки.

| Показатель | До, холодный | После, холодный | До, тёплый | После, тёплый |
| --- | ---: | ---: | ---: | ---: |
| Крупный портрет | 15 576 мс | 3490 мс | 782 мс | 269 мс |
| Лёгкая версия портрета | — | 694 мс | — | 269 мс |
| Иконка активки | 19 065 мс | 600 мс | 1128 мс | 270 мс |
| Все аватары | 22 352 мс | 3660 мс | 1594 мс | 267 мс |

Один парный прогон, не статистическая оценка и не гарантия для опубликованного сайта. Изменения уменьшают раннюю конкуренцию за сеть; полная готовность боя на этом профиле отдельно не измерялась. Артефакты и сценарий: игнорируемая папка `output/fast4g/`.

Проверены все 15 выборов, мобильный экран, открытие улучшений по запросу и резервная загрузка после ошибки атласа. Ошибок JavaScript в сравнении нет. 337 тестов, TypeScript, production build и проверки обоих генераторов проходят. Новый тест подтверждает отсутствие загрузок при audio unlock, общую подготовку звуков, отсутствие воспроизведения старых выстрелов и сохранение громкости взрыва.
