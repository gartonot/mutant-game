# Игровой цикл и большие волны — 21 октября 2026

## Что изменено

- Симуляция выполняется с шагом 1000/60 мс, отрисовка — через requestAnimationFrame. Скорость движения больше не зависит от частоты монитора. Параметры движения сохранены в прежних единицах на один шаг 60 Гц.
- На кадр разрешено не более пяти шагов догоняющей симуляции. Избыточное время учитывается как `droppedSimulationMs`, а не превращается в бесконечную очередь работы. При длительной перегрузке игра замедляет симуляцию; это защита, а не обещание неограниченной производительности.
- Пауза и скрытая вкладка сбрасывают накопитель. Оружие, контактный урон, взрыватель, волны и эффекты используют время симуляции. FPS считается по отрисовкам.
- Ввод, движение и снаряды обновляются перед столкновениями текущего шага. Игрок больше не обновляется второй раз из main.
- Пространственная сетка отбирает цели снарядов и соседние пары врагов. Отбрасывание удалённых объектов использует квадраты расстояний. Сетка учитывает большие радиусы и отрицательные координаты; после отбрасывания цели её ячейка обновляется.
- Быстрые снаряды проверяются по отрезку движения и попадают в первую пересечённую цель. Выход за экран не удаляет снаряд до проверки последнего отрезка.
- Раздвигание толпы рассчитывается по снимку позиций, после чего применяются ограниченные смещения. Это устраняет зависимость поиска соседей от промежуточных перемещений. Поведение сильно сжатой толпы отличается от прежнего последовательного решателя; в одном шаге не гарантируется устранение всех пересечений.
- Удаление умерших объектов выполняется на месте. У следов пуль — кольцевой буфер фиксированного размера и одна градиентная линия вместо сотни отдельных stroke. Свечение головки пули растеризуется один раз и повторно используется.
- Очистка canvas выполняется в координатах буфера без DPR-преобразования: при масштабе браузера меньше 100% больше не остаются старые кадры у правого и нижнего края.
- Исправлены двойной контактный урон, деление на ноль при совпадающих центрах, а также учёт промаха гранаты, которая не попала ни в одну цель.

## Сравнение столкновений

Node 24.19.0, этот компьютер. Один шаг поиска попаданий и раздвигания врагов, без отрисовки, движения и создания сцены. Для каждой реализации 10 прогревочных и 25 измеряемых повторов; порядок чередуется. Случайные данные воспроизводятся seed=42. Исходный алгоритм сохранён в `scripts/bench/LegacyCollisionSystem.ts` и `legacySeparation` исключительно для измерений.

| Сцена | До, медиана / p95, мс | После, медиана / p95, мс |
|---|---:|---:|
| 1000 врагов, 300 пуль, 1920×1080 | 8.119 / 11.228 | 1.388 / 2.367 |
| 3000 врагов, 1000 пуль, 1920×1080 | 64.405 / 69.272 | 3.370 / 4.207 |
| 3000 врагов, 1000 пуль, скопление 500×500 | 39.602 / 43.920 | 5.135 / 7.971 |

Для второй сцены: около 19 раз быстрее по медиане. Число фактических узких проверок новой версии — 44 274; полный перебор имеет до 7 498 500 пар. Последнее число — верхняя оценка: прежний алгоритм тоже пропускал мёртвые объекты.

`performance-baseline.json` содержит первый отдельный замер до оптимизации. Для итогового сравнения используется `performance-comparison.json`: измерения обеих версий выполнены вперемежку в одном процессе. Разница между отдельными запусками ожидаема из-за JIT, сборщика мусора и фоновой нагрузки. Алгоритмы стартуют с одинаковых сцен, но не обязаны давать побитово одинаковые конечные позиции: порядок попаданий и решатель толпы исправлены.

## Отрисовка и полный нагрузочный сценарий

Microsoft Edge, окно браузера через Playwright, canvas 1920×1080. Отдельный тест 300 заполненных следов: медиана 59.4 → 5.1 мс; p95 74.5 → 5.9 мс. Измерение включает чтение одного пикселя для отправки canvas-команд и не эквивалентно GPU frame time.

Затем 600 кадров с 3000 движущихся врагов и 1000 отрисовываемых снарядов, первые 30 кадров исключены из статистики. Снаряды наносят нулевой урон и возобновляются после попаданий/выхода, чтобы нагрузка не исчезала. В тесте рисуются все 1000, в том числе разрешённые на текущем шаге. Игрок, меню и интерфейс не входят в этот синтетический сценарий; обычный бой проверен отдельно.

| Метрика итогового теста | Медиана | p95 |
|---|---:|---:|
| CPU симуляции на кадр, включая догоняющие шаги | 5.6 мс | 10.1 мс |
| Отправка команд отрисовки | 4.2 мс | 6.7 мс |
| Интервал requestAnimationFrame | 10.1 мс | 20.1 мс |

Потеря времени симуляции: 0 мс после прогрева, 0 мс при прогреве. До кеширования свечения, но уже с новой сеткой и следами, медианный интервал был 40.1 мс, p95 — 50.2 мс. Сырые браузерные результаты: `performance-browser.json`.

Это локальные результаты, а не гарантия 60 FPS на любом устройстве. Вырожденная сцена, где все враги находятся в одной точке, всё ещё имеет квадратичное число реальных соседей. Её корректность проверена тестом, но не заявлена как игровая нагрузка с фиксированным FPS. Интерполяция отрисовки между шагами пока не добавлена.

## Повторить измерения

1. `npm test` — регрессионные проверки.
2. `npm run build` — типы и production-сборка.
3. `npm run bench` — сравнение столкновений в Node. `node scripts/run-bench.mjs baseline` — отдельный старый алгоритм.
4. `npm run dev`, затем `/profile.html` — сравнение столкновений, следов и нагрузка на браузер. Перед полным тестом перезагрузить страницу: чтение пикселя в тесте следов может изменить canvas backend. Держать вкладку на переднем плане; для более строгого сравнения закрыть другие тяжёлые страницы.
5. Обычная игра с `/?profile`: `window.mutantProfile()` возвращает медиану, p95 и потерянное время. Буфер ограничен последними 600 активными кадрами, пауза не записывается. Без параметра замеры времени отключены.

Нагрузочная страница служит разработке и не включается стандартным Vite build. Бенчмарк не ставит пороги времени в unit-тестах, чтобы CI не падал от колебаний производительности.
