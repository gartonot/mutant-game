# Повторная проверка загрузок — 31 октября 2026

Исторический отчёт: измерения ниже относятся к состоянию 31 октября. Актуализация 1 ноября 2026: каталог оружия уже использует атлас и встроенные превью через `EquipmentArtwork.ts`; старый генератор каталожных иконок удалён. Скриншоты и экспериментальные изображения из `output` удалены при согласованной очистке, сценарии и JSON сохранены. Упоминания удалённых изображений ниже описывают материалы первоначальной проверки.

## Исправлено: активки на клик персонажа

Набор из 13 активок теперь используется через один атлас 768×768, 165 338 байт. Загрузка начинается при создании приложения, в главном меню. Экран выбора меняет только координаты ячейки; боевой HUD использует тот же декодированный атлас. Пробные облики не получают выдуманных активок. Генератор `scripts/optimize-abilities.mjs` сохраняет оригиналы и проверяет атлас/координаты через `--check`.

Проверено в Edge: один запрос активок до открытия выбора, 13 различных ячеек, ноль дополнительных запросов активок при переключении всех 15 героев, успешный старт боя, без ошибок JS. Артефакты: `output/fast4g/ability-atlas-check.cjs`, `ability-atlas.png`. 337 тестов, TypeScript и production build проходят. При холодном старте сам общий атлас всё равно требует скачивания; заранее подготовленная карточка не означает нулевое время первого открытия страницы.

## Замечания исходного аудита и последующие изменения

Это список найденных тогда мест, а не новый замер задержек текущей версии. Проверка опубликованной игры завершена пользователем; статус отражён в [bugs.md](bugs.md).

1. `AmmoArt.ts`, `BonusArt.ts`: загрузка начинается из отрисовки при первом показе HUD/выпадения. Пять иконок патронов — 320 634 байта, 14 бонусов — 1 505 980 байт. Карты сохраняют неудачные ImageAsset без повторной попытки. Подготовить компактный набор заранее и добавить повтор после сетевой ошибки; не переносить весь текущий объём в первый экран.
2. `PortraitPreloader.ts`, `GameApplication.ts`: после готовности UI начинается очередь всех крупных портретов, все боевые картинки и 21 звук. При новом выборе уже начатые запросы конкурируют за сеть даже с низким приоритетом. Ограничить предзагрузку портретов соседями/hover/focus, готовить боевые ресурсы ограниченной очередью.
3. **Устранено последующей переработкой каталога:** прежняя схема ожидала все 19 моделей оружия. Сейчас `EquipmentArtwork.ts` использует атласы оружия и бонусов со встроенными превью; два атласа завершают подготовку независимо, ошибка допускает повтор. Неиспользуемый старый Canvas-генератор и каталожная ветка `WeaponSprites.ts` удалены. Подробности: [equipment-loading-2026-10-31.md](equipment-loading-2026-10-31.md).
4. `CombatAudio.ts`: preloadStarted остаётся true после ошибок отдельных файлов; пропущенные звуки не повторяются до перезагрузки. Нужны независимые повторяемые состояния загрузки файлов.

## Требует сетевого измерения

Музыка меню использует preload auto и play на старте; весь файл 1 055 161 байт. Фактически скачанный буфер и конкуренцию с картинками нужно проверить в waterfall. Размер файла сам по себе не подтверждает, что он целиком скачивается при открытии.

Достижения (два небольших SVG) и подсказки улучшений (те же уже запрошенные URL) аналогичной проблемы не показали. Этот список — результат чтения кода; задержки перечисленных оставшихся мест отдельно не измерялись.
